# 两江新区数智健康管理服务平台 · 应标高保真演示系统

依据《第3章 两江新区数智健康管理服务平台》49 页功能需求构建的高保真交互系统。以 **10 项 ★ 现场演示 + 7 项 ▲ 功能截图** 为主线，覆盖“采集—治理—指标—标签—资产—服务”的端到端故事，并按招标口径重组为统一门户、数据采集与治理、数据中台、业务中台四个工作域。

> 定位：**应标演示 / 方案验证系统**。已接入 PGlite 数据库连接层（`.data/pglite`），数据库连接层页、只读查询与审计走真实接口；采集方案页与数据库连接层页已走真实接口，其余演示页面仍以演示数据为主。未接统一认证、未做信创认证。不是生产系统。

## 快速启动

环境要求：Node.js 18+（已在 Node 24 验证）。

```bash
npm install
npm run dev        # Next.js 开发模式 + API，默认 5188
# 打开 http://127.0.0.1:5188/bid/home

# 生产
npm run build
npm start
```

macOS 可双击 `启动演示.command`，自动构建、启动并打开浏览器。

- 开发：`npm run dev`（Next.js custom server，热更新）
- 生产构建：`npm run build`（输出到 `.next/`）
- 生产启动：`npm start`
- 停止服务：`Ctrl+C` 或 `pkill -f 'server/index.js'`
- 重置数据库：`npm run db:reset`（删除 `.data/pglite`，下次启动重新迁移/灌数）
- 端口占用：`PORT=5189 npm start`

## 顶部导航顺序

顶部导航按数据生命周期和招标章节顺序规划：

```text
统一门户 → 数据采集与治理 → 数据中台 → 业务中台
```

- 统一门户：入口、驾驶舱、演示与对标
- 数据采集与治理：数据进来、标化、入湖、质量
- 数据中台：标准、指标、标签、资产、服务
- 业务中台：统一认证、共享、流程、平台管理

不按开发顺序、页面数量或菜单多少排列；管理后台归入业务中台，避免出现第五个顶部入口。

## 拖拽采集与数据进仓

采集方案页：`/bid/collection-wizard`

- 左侧节点库拖入画布：HIS 患者、LIS 检验、EMR 就诊、达梦、API/文件
- 连线到“字段标准化”，再连到“ODS 入仓”
- 右侧配置物理表、别名、抽取策略、目标表前缀
- 点击“运行入仓”，后端按当前连线真实写入 `warehouse.ods_health_*`
- 下方“数据预览”直接读取 PGlite 入仓表
- 演示快捷入口：`/bid/collection-wizard?run=1&shot=1`（自动运行并展示预览）

> 入仓当前按数据源复制到 `warehouse.<前缀>_<别名>`，用于验证链路；生产环境应替换为字段映射、增量合并与质量校验后的 DWD 写入。

## 数据查询工作台

`/bid/data-query`

- **资源树**：ODS / DWD / DIM / warehouse 分层，表可展开字段，点击表名插入 `SELECT`，点击字段插入列名
- **历史目录**：按“运营分析 / 门诊”等目录保存查询，支持检索、加载、删除；最近执行记录可回填 SQL
- **函数库**：聚合、窗口、日期、文本/JSON 函数片段，点击插入光标
- **在线脚本**：SQL 编辑器、行号、语法高亮、格式化、`⌘/Ctrl + Enter` 运行、`⌘/Ctrl + S` 保存
- **实时预览**：自动运行可开关；结果支持表格分页、柱状/折线/占比图、CSV 导出、执行计划
- 后端真实执行 `/api/query`，只读、最多 200 行、写审计；保存目录落到 PGlite `saved_queries`

示例入口：`/bid/data-query?shot=1`

## 系统结构

- **统一门户**：首页大屏、演示清单、功能对标、数据库连接层
- **数据采集与治理**：采集、实时通道、数据预览、监控、质控、知识库、标准文档
- **数据中台**：标准、元数据、指标、标签、主档案、资产、开放服务
- **业务中台**：统一认证、应用与权限、审计与平台管理

技术：Next.js 15（App Router）+ React 19 + TypeScript；自定义 server 同端口托管页面与 `/api`；后端 Node.js + PGlite；采集画布使用 React Flow；自研组件与 SVG 图表。

## 演示建议

1. **数据从哪来（约 8 分钟）**：采集方案 → 实时通道 → 数据预览 → 数据查询 → 监控总览。
2. **质量怎么保（约 8 分钟）**：五维规则 → 评分模型 → 质控流程 → 质控结果 → 知识库。
3. **价值怎么用（约 8 分钟）**：指标市场 → 标签看板 → 居民主档案 → 资产管理 → 资产发布 → 首页大屏。

## 数据库连接层

默认启动 PGlite（嵌入式 PostgreSQL），数据目录 `.data/pglite`；启动时自动迁移并灌入演示数据。

```bash
npm start                 # PGlite
DB_DRIVER=postgres \
DATABASE_URL=postgres://user:pass@host:5432/health npm start
```

分层：`页面 → /api 模块 → Service → Repository → DatabaseAdapter → DB`。业务模块不 import PGlite / pg，只依赖 `query / transaction / health` 契约；新增数据库只需实现 Adapter。

模块可切片：`MODULES=institutions,catalog,assets npm start` 只挂载指定模块；模块清单集中在 `server/modules/index.js`。

当前已接入：机构、数据目录/元数据、资产、质量、指标、居民主索引、实时通道、只读查询与审计，以及拖拽采集入仓。采集方案页与数据库连接层页已走真实 API；其余页面仍在逐步从 mock 切换。
