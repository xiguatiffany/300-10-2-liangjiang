# 数据库接入与信创适配说明

> 适用对象：MedData 医疗数据中台产品原型（当前版本 v1.0）
> 结论口径：本说明用于技术评估，不构成任何“信创认证”“等保测评”或“医疗器械/软件产品认证”结论。

## 一、当前版本的真实性边界

| 项目 | 当前状态 |
| --- | --- |
| 页面与交互 | 真实可运行，可点击、筛选、排序、查询、编辑、提交 |
| 数据 | 内置模拟数据（`src/data.ts`），不是医院真实数据 |
| 后端服务 | 无 |
| 数据库连接 | 无，当前不连接任何数据库 |
| 登录 / 权限服务 | 前端模拟，无真实认证与令牌 |
| 数据持久化 | 页面级内存状态，刷新后临时修改重置 |
| 部署形态 | 静态前端（Vite 构建），可用 Nginx 托管 |

因此：**当前版本适合作为产品评审、界面确认、需求沟通和投标演示的原型，不能直接接入医院生产数据库，也不能作为生产系统上线。**

## 二、接入真实数据库需要增加什么

### 2.1 推荐技术架构

```
浏览器（MedData 前端）
      │ HTTPS / JSON
      ▼
API 网关（Nginx / 东方通 / 宝兰德）
      │
      ▼
业务后端（Java 17 + Spring Boot 3）
  ├─ 认证授权：CAS / OAuth 2.0 / LDAP，RBAC + 数据权限
  ├─ 数据源管理：JDBC 连接池、连接测试、密钥加密
  ├─ 元数据服务：库表结构、字段、主键、注释采集
  ├─ 查询服务：只读 SQL 执行、行数/超时限制、结果脱敏
  ├─ 采集调度：SeaTunnel / DataX / Flink CDC + DolphinScheduler
  └─ 审计服务：登录、查询、导出、配置变更全量留痕
      │
      ▼
数据库层：达梦 DM8 / 人大金仓 KingbaseES / openGauss /
          OceanBase / TiDB / MySQL / Oracle / SQL Server / PostgreSQL
```

### 2.2 最小可验证 PoC（建议先做）

目标：让“服务注册 → 元数据加载 → 数据查询”三个页面读取真实数据库，而不是模拟数据。

1. 提供一台测试数据库（MySQL / PostgreSQL 即可）和只读账号。
2. 新增 Spring Boot 服务与以下接口：
   - `POST /api/datasources/test`：连接测试
   - `POST /api/datasources`：保存数据源（密码加密）
   - `GET  /api/datasources/{id}/tables`：读取库表清单
   - `GET  /api/datasources/{id}/tables/{table}/columns`：读取字段
   - `POST /api/query/execute`：只读查询（限制 1 万行、30 秒超时）
   - `GET  /api/query/history`：查询历史
3. 前端把 `src/data.ts` 中对应页面的数据替换为 API 调用，保留现有交互与视觉。
4. 加入最小审计：谁、何时、从哪个 IP、查了哪张表、返回多少行。

PoC 验收标准：
- 在界面上新增真实数据源并测试连通；
- 自动读取真实表/字段；
- 在 SQL 工作台执行 `SELECT` 并返回真实结果；
- 所有查询可在审计日志中追溯；
- 数据库账号为只读，无法执行 DDL/DML。

### 2.3 生产化必须补齐

- 数据源密码使用国密 SM4 或 AES-256 加密存储，密钥与配置分离；
- SQL 解析与白名单：禁止 `DROP/DELETE/UPDATE/INSERT/ALTER`，限制笛卡尔积、全表扫描和超大结果集；
- 行级/列级数据权限、动态脱敏、导出审批；
- 采集链路的断点续传、幂等、对账、失败重试与告警；
- 统一身份认证、会话管理、双因素认证；
- 等保三级要求的安全审计、日志留存、入侵防范、数据备份；
- 压测与容量规划（并发查询、元数据规模、采集吞吐）。

## 三、信创适配判断

### 3.1 结论

**当前版本不能宣称“符合国产信创”。** 原因不是界面不能运行，而是：

1. 没有国产软硬件环境的实际适配与测试记录；
2. 没有后端、数据库、中间件等国产生态组件；
3. 没有国密支持、等保测评、信创产品认证或互认证明；
4. 当前代码仍包含外网字体依赖（本轮已移除，改为系统字体栈），但整体尚未做内网离线验证。

“信创”不是单一开关，而是**目标目录 + 实际测试 + 认证/互认**的组合。不同医院、不同省份的信创目录要求可能不同，最终以用户单位发布的技术要求为准。

### 3.2 可适配的技术路线

| 层级 | 可选国产化路线 | 当前版本情况 |
| --- | --- | --- |
| CPU | 鲲鹏 920、飞腾 S2500、海光、龙芯 3A5000 | 未验证 |
| 操作系统 | 麒麟软件 Kylin V10、统信 UOS 服务器版 | 未验证 |
| 浏览器 | 奇安信可信浏览器、360 安全浏览器、红莲花 | 仅 Chrome 内核验证 |
| 前端 | React / Vue 静态资源，本地字体，无外部 CDN | 可改造，已去除 Google Fonts |
| 后端 | Java 17（OpenJDK / 毕昇 JDK / Dragonwell） | 尚未建设 |
| 应用服务器 | 东方通 TongWeb、宝兰德 BES、Nginx | 尚未建设 |
| 数据库 | 达梦 DM8、人大金仓 KingbaseES、openGauss、OceanBase、TiDB | 尚未接入 |
| 中间件 | 东方通、宝兰德、金蝶 Apusic | 尚未接入 |
| 密码 | SM2 / SM3 / SM4 国密算法 | 尚未接入 |
| 安全 | 等保三级、数据分类分级、脱敏、审计 | 尚未测评 |

### 3.3 前端信创兼容注意事项

- 不引用境外 CDN、外部字体、外部统计脚本；
- 构建产物本地化，使用相对路径部署（当前已使用 `base: './'`）；
- 使用国产浏览器内核做兼容性回归（Chrome 90+ 内核基本可用，但需实测）；
- 大屏/低版本浏览器降级方案；
- 若客户要求“全国产前端框架”，可将 React 替换为 Vue 3 + 国产 UI 组件库，但界面与接口层可复用。

## 四、建议实施阶段

| 阶段 | 内容 | 产出 |
| --- | --- | --- |
| P0 原型（当前） | 高保真界面、交互、演示数据 | 可点击产品原型 |
| P1 真实连接 PoC | 后端 + 1 个真实数据库 + 查询/元数据/审计闭环 | 可演示的真实连库版本 |
| P2 产品化 | 权限、采集、对账、质量、调度、监控完整后端 | 可部署测试环境 |
| P3 信创适配 | 国产 OS/CPU/DB/中间件/浏览器 + 国密 + 等保 | 适配报告、测试记录、认证材料 |

## 五、需要院方/甲方提供的信息

1. 目标数据库类型与版本（如达梦 DM8、金仓 V8、MySQL 8.0）；
2. 数据库网络位置、端口、白名单与只读账号（PoC 用）；
3. 目标信创目录（操作系统、CPU、数据库、中间件、浏览器）；
4. 是否需要国密、等保三级、数据分类分级；
5. 部署环境是院内网、政务云还是信创云。

在拿到上述信息前，任何“已符合信创”的表述都不严谨。当前版本可以作为**信创适配的界面与交互基线**，但不能替代适配测试与认证。
